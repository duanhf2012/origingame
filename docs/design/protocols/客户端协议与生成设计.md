# OriginGame 客户端协议与生成设计

> 状态：目录与生成规则已确认
> 更新日期：2026-08-13

## 1. 目录

客户端与服务端共享的 Protobuf 契约统一平铺在：

```text
protocol/common/
├── errorcode.proto
└── errorcode.pb.go
```

后续只在出现真实协议时增加 `messageid.proto`、`gateway.proto`、`player.proto` 等具体文件，当前不按版本或业务域增加子目录。

`.proto` 是唯一协议源；服务端 `.pb.go` 与源文件同目录并提交仓库。Protobuf 包固定为 `origingame.protocol`，Go 包固定为 `origingame/protocol/common;commonpb`。

## 2. 内容边界

`protocol/common` 只保存客户端需要共同理解的枚举和消息，包括客户端错误码、消息 ID、请求、响应及服务端主动推送。以下内容不得进入该包：

- MongoDB BSON 文档；
- 只供 HTTP 使用的 JSON DTO；
- Service 内部运行状态；
- Service 间 RPC 专用参数。

HTTP 可以在已经确认的接口中使用客户端错误码数值，但 HTTP DTO 不因此成为 Protobuf 契约。

## 3. 兼容规则

- 已发布字段号和枚举值不得改变含义或分配给其他成员；
- 删除字段或枚举时必须保留原编号和名称；
- 新客户端必须能把未知错误码降级为通用内部错误；
- 不兼容变更必须先设计新的协议版本边界，不能直接修改现有线上含义。

MessageID 分配和静态消息注册表生成将在 Gateway 客户端消息协议最终字段确认时单独设计，不在当前只有错误码的阶段预建生成器。

## 4. 生成

生成环境固定使用 `protoc 24.0` 和 `protoc-gen-go 1.31.0`。Windows 执行 `scripts\generate.bat`，Linux/macOS 执行 `scripts/generate.sh`；提交前执行对应的 `scripts/check-generated.*`，确认生成物与源文件一致。

生成代码不得手工修改。升级生成器版本必须单独评估并提交全部可重复生成的差异。
