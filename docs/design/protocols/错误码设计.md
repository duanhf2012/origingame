# OriginGame 客户端错误码设计

> 状态：第一版错误码基线
> 更新日期：2026-08-15

## 1. 定义方式

客户端可见错误码统一定义在共享 Protobuf 文件中，例如：

```text
protocol/common/errorcode.proto
```

建议定义：

```proto
syntax = "proto3";

package origingame.protocol;

option go_package = "origingame/protocol/common;commonpb";

enum ErrorCode {
  ERROR_CODE_OK = 0;

  ERROR_CODE_INTERNAL = 1;
  ERROR_CODE_INVALID_REQUEST = 2;
  ERROR_CODE_TOO_MANY_REQUESTS = 3;

  ERROR_CODE_LOGIN_PLATFORM_TYPE_INVALID = 1000;
  ERROR_CODE_LOGIN_PLATFORM_ID_INVALID = 1001;
  ERROR_CODE_LOGIN_PLATFORM_UNSUPPORTED = 1002;
  ERROR_CODE_LOGIN_AUTH_FAILED = 1003;
  ERROR_CODE_LOGIN_ACCOUNT_FAILED = 1004;
  ERROR_CODE_LOGIN_NO_AVAILABLE_AREA = 1005;

  ERROR_CODE_GATEWAY_TOKEN_INVALID = 2000;
  ERROR_CODE_GATEWAY_LOGIN_IN_PROGRESS = 2001;
  ERROR_CODE_GATEWAY_ALREADY_LOGGED_IN = 2002;
  ERROR_CODE_GATEWAY_NOT_LOGGED_IN = 2003;
  ERROR_CODE_GATEWAY_AREA_NOT_FOUND = 2004;
  ERROR_CODE_GATEWAY_ROUTE_UNAVAILABLE = 2005;
  ERROR_CODE_GATEWAY_PROTOCOL_ERROR = 2006;
  ERROR_CODE_GATEWAY_LOGGED_IN_ELSEWHERE = 2007;
}
```

## 2. 编号范围

| 范围 | 用途 |
| --- | --- |
| `0` | 成功 |
| `1–999` | 全局公共错误 |
| `1000–1999` | LoginService |
| `2000–2999` | GatewayService |
| `3000–9999` | 后续公共基础服务 |
| `10000` 及以上 | 游戏业务服务，后续按模块继续分段 |

已经发布给客户端的数值不得改变含义或重复使用；删除的错误码使用 Protobuf `reserved` 保留编号和名称。

## 3. HTTP 使用规则

- LoginService 成功响应返回 `ECode = ERROR_CODE_OK`；
- 登录失败响应只返回 `ECode`，不返回空 Token、空区服列表或额外错误文本；
- 业务失败的错误码直接使用 Protobuf 枚举的数值；
- 服务端详细错误写入日志，不把 MongoDB、SDK、Token 或内部节点信息返回客户端。

第一版保留老版本的数值 `ECode` JSON 字段，避免客户端依赖 Protobuf 枚举名称的 JSON 表示。

## 4. Gateway 使用规则

Gateway 响应消息头中的 `ErrorCode` 使用同一个 Protobuf 枚举的 `int32` 数值。`0` 表示成功，非零值表示失败。

错误响应没有额外数据时，Protobuf Body 可以为空。客户端对未知错误码按通用内部错误处理，以便服务端和客户端版本短期不完全一致时仍可安全降级。

`ERROR_CODE_GATEWAY_LOGGED_IN_ELSEWHERE`用于新连接登录同一Player时通知旧连接。顶号是`Sequence = 0`的服务端主动推送，该错误码放在`PlayerKickedNotify.reason`中；Gateway在完整写入该推送后关闭旧连接。
