# 登录链路监控与测试设计

> 状态：业务监控、慢处理、告警和测试验收已确认
> 更新日期：2026-08-22

## 1. 适用范围

本文只定义从LoginService HTTP登录、Gateway登录分配到GameService加载Player并进入Online的跨Service监控与测试规则。各Service只保留自身业务统计；HTTP、网络、RPC、Service调度和DBService的通用统计直接复用Origin或对应基础设施能力，不重复采集。

监控实现遵守以下统一规则：

- NodeID、ServiceName由采集器作为资源属性附加，不作为业务指标标签；
- 禁止把AccountID、PlayerKey、GatewayConnectionID、Redis Key或Script ID作为指标标签；
- 标签值只能来自本文固定的低基数枚举；
- 高频网络路径只更新Origin网络Module已有的固定原子统计，不增加逐消息Histogram、字符串格式化或动态指标对象；
- 登录、Player加载等低频路径允许使用固定Bucket Histogram，采样时不得产生逐请求动态标签；
- OriginGame通过固定Stats快照和监控适配层输出，不直接绑定Prometheus或其他第三方监控SDK。

## 2. 业务监控字段

### 2.1 LoginService

| 指标 | 类型 | 注释 |
| --- | --- | --- |
| `loginservice_login_total{outcome}` | Counter | HTTP登录结果数量；`outcome`固定为`success`、`rate_limited`、`auth_failed`、`dependency_failed`、`internal_error` |
| `loginservice_login_duration_seconds{outcome}` | Histogram | 一次HTTP登录从收到请求到响应完成的真实系统耗时 |
| `loginservice_rate_limited_total{dimension}` | Counter | 各限流维度拒绝次数；`dimension`固定为`ip`、`identity`、`concurrency` |
| `loginservice_area_refresh_total{outcome}` | Counter | 区服快照刷新成功或失败次数；`outcome`固定为`success`、`failure` |
| `loginservice_area_last_success_timestamp_seconds` | Gauge | 最近一次区服快照刷新成功的Unix真实系统时间；监控端用当前时间减该值计算快照年龄 |

不单独输出区服快照年龄，避免Service持续更新时间Gauge。

### 2.2 GatewayService

| 指标 | 类型 | 注释 |
| --- | --- | --- |
| `gateway_sessions{state}` | Gauge | 当前业务会话数；`state`固定为`connected`、`logging_in`、`online` |
| `gateway_login_total{outcome,failure_stage}` | Counter | Gateway登录结果和失败阶段；成功时`failure_stage=none`，失败阶段固定为`token`、`area`、`route`、`gameservice` |
| `gateway_login_duration_seconds{outcome}` | Histogram | 从收到客户端登录消息到完成登录响应的真实系统耗时 |
| `gateway_message_rate_limited_total` | Counter | 单连接在10秒窗口内超过200条消息并被关闭的次数 |

活动连接、累计收发消息与字节、协议错误、队列过载和慢连接关闭直接使用TCP、KCP、WebSocket各自的Origin网络Module `EndpointStats`，Gateway不重复维护。

### 2.3 GameService

| 指标 | 类型 | 注释 |
| --- | --- | --- |
| `gameservice_players{state}` | Gauge | 当前Player数量；`state`固定为`loading`、`online`、`resident`、`releasing` |
| `gameservice_player_capacity` | Gauge | 当前实例配置的`player_capacity`，用于和各状态Player总数计算容量利用率 |
| `gameservice_player_load_total{outcome,failure_stage}` | Counter | Player加载结果及失败阶段；失败阶段固定为`none`、`database`、`decode`、`on_loaded`、`on_all_loaded`、`initial_save` |
| `gameservice_player_load_duration_seconds{outcome}` | Histogram | 从创建Player到数据加载和初始化完成的真实系统耗时 |
| `gameservice_player_load_bytes` | Histogram | 本次登录从RoleDBService取得的BSON文档总字节数，用于发现大Player |
| `gameservice_dirty_players` | Gauge | 当前至少存在一份脏持久化数据的Player数量 |
| `gameservice_player_save_total{trigger,outcome}` | Counter | 各类存档结果；`trigger`固定为`periodic`、`offline`、`release`、`shutdown` |

Player加载Operation数量只进入慢日志，不增加指标；DBService已经输出请求Operation数量和数据库耗时。

### 2.4 PlayerRoute

| 指标 | 类型 | 注释 |
| --- | --- | --- |
| `player_route_operations_total{operation,outcome}` | Counter | 分配、状态转换、续租和释放等路由操作结果；两类标签只能使用代码固定枚举 |

路由耗时和公共Redis错误直接使用DBService RPC及Redis执行指标；实例分配数由`gameservice_players`和`gameservice_player_capacity`计算，不增加重复指标或`node_id`标签。

## 3. 慢处理与告警

首期使用以下代码固定参考线，不增加运行配置：

| 条件 | 处理 |
| --- | --- |
| Gateway完整登录超过`2s` | 输出一条限频WARN慢日志 |
| GameService Player加载超过`1s` | 输出一条限频WARN慢日志 |
| 单个Player登录常驻数据超过`1MiB` | 输出WARN；告警直接使用`gameservice_player_load_bytes`直方图，不增加重复Counter |
| 最终存档失败 | 立即输出ERROR，不因限频完全隐藏 |
| 玩家路由Redis操作持续失败超过`30s` | 告警公共Redis或AccDBService异常 |
| GameService已分配Player达到`player_capacity`的`90%` | 告警实例接近容量 |

同一类慢日志按`service + stage + outcome`每10秒最多输出一条；被抑制数量必须保留累计计数。限频只影响日志，不影响监控统计。

结构化日志只允许记录稳定阶段、结果、耗时、Operation数量、结果字节数、RealAreaID、ShowAreaID、ServiceName和NodeID。需要关联单个玩家时记录不可逆`player_key_hash`，不得记录Token、AccessToken、原始PlayerKey、GatewayConnectionID、BSON、Redis Key/Value或客户端消息Body。

## 4. 测试验收

### 4.1 单元测试

- Proxy注册顺序、正序回调和倒序释放；
- 首次创建、部分集合已有数据和初始保存失败；
- 脏代数在存档期间再次修改时不会被错误清除；Player独立Timer按PlayerKey错峰、释放后不再Tick；
- Gateway登录状态机、30秒Deadline和10秒消息限流窗口；
- PlayerRouteStore的Key、参数、整数返回码转换和状态判断。

### 4.2 集成测试

- MongoDB多Operation批量加载、结果下标对应、部分失败和4MiB边界；
- Redis并发分配只产生一个玩家所有者；
- GameService容量、实例租约、玩家TTL、LEAVING 5秒窗口和条件回滚；
- 公共Redis不可用时拒绝新登录，已有Player继续处理不依赖AccDBService的业务，恢复后重新登记和续租；
- Gateway、GameService通过AccDBService和RoleDBService的实际RPC路由。

### 4.3 进程级E2E与性能验证

进程级E2E和压测由隔离测试Node上的[RobotService](services/RobotService设计.md)通过真实LoginService HTTP入口和Gateway客户端协议执行。RobotService不直接调用内部业务RPC或数据库；负载生成器自身资源、队列拒绝和实际创建速率必须与服务端指标同时记录，避免把压测机瓶颈误判为服务器容量。

- 首次登录、同连接重复请求、断线重连、顶号和15分钟驻留释放；
- GameService宕机、Redis不可用、DBService过载或查询失败时不会产生两个Player；
- 4KB客户端消息上限、10秒200条限流及非法协议关闭；
- `go test -race`覆盖连接索引、Player生命周期、停止排空和路由恢复；
- 保留普通Go RPC静态Codec、客户端消息转发、Player批量加载和Redis分配Benchmark；首期记录基线和P50/P95/P99，不规定脱离硬件环境的固定吞吐数字。
